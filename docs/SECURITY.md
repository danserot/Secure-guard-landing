# Защита сайта — 19 октября 2026

## Что действует и где

`frontend/nginx.conf` применяется в production-контейнере. Vite dev и preview
не используют nginx. Обработчик Google Apps Script обновлён на действующем URL
до версии 2; его квоты работают независимо от способа публикации frontend.

### Nginx

| Ограничение | Значение |
| --- | --- |
| Статические страницы, на один IP | 15 запросов/с, burst 80 |
| API, на один IP | 10 запросов/с, burst 30 |
| Вход, на один IP | 5 запросов/мин, burst 5 |
| Инференс, на один IP | 2 запроса/с, burst 3 |
| Суммарно | 200 запросов/с, burst 400 |
| Одновременные обрабатываемые соединения | 32/IP, 512 суммарно |
| Тело обычного запроса / входа | 16 KiB |
| Инференс / загрузка доказательств через API | 4 MiB / 34 MiB |
| Ожидание заголовков / тела | 10 с / 15 с |

При превышении частоты или соединений сервер возвращает HTTP 429 и `Retry-After: 60`.
Burst допускает короткий всплеск сверх основной частоты; это не жёсткий счётчик
запросов за календарную секунду. Значения требуют настройки по реальному трафику.

Скрыты версия nginx и `X-Powered-By`, запрещены листинг каталога, скрытые файлы,
дампы, логи и source maps. Для отсутствующих статических ресурсов возвращается 404.
Публичная статика принимает GET/HEAD, вход — POST. Клиентский `X-Forwarded-For`
перезаписывается адресом соединения. `/api/` имеет приоритет перед regex-локациями.

Добавлены `nosniff`, запрет iframe, Referrer-Policy, Permissions-Policy и COOP.
CSP для `/landing` и `/landing/` разрешает скрипты своего сайта и соединение
с Google intake. Для существующей панели строгая CSP не введена: её камера,
WASM и отдельный API требуют отдельной проверки. TLS и HSTS настраиваются
на HTTPS-прокси хостинга; этот контейнер слушает внутренний HTTP.

### Заявки в Google Sheets

- Тело до 10 000 байт UTF-8; только JSON в `application/json` или `text/plain`.
- Проверяются разрешённые поля, типы, длины, контакт, согласие и управляющие символы.
  Пользовательские формулы экранируются; ошибки не раскрывают данные и детали Google.
- Постоянные глобальные квоты: 30 валидных запросов/мин, 300/час, 1000/сутки.
  Проверяются под блокировкой до обращения к таблице. Используются UTC-окна;
  на границе окон возможен короткий двойной всплеск.
- Не более трёх новых заявок на нормализованный контакт за час. В Properties
  сохраняются SHA-256 контактов и счётчики, без открытых телефонов/email.
- Таблица ограничена 10 000 заявок. При достижении лимита требуется обработать
  и архивировать данные, затем проверить приём. Автоматического удаления нет.
- UUID предотвращает повторную запись. Кэш ускоряет квитанции, но не хранит квоты;
  при его очистке или сбое остаётся проверка UUID по таблице.
- Ожидание блокировки — до 100 мс, затем `BUSY` с паузой 3 с. При недоступности
  постоянных квот новые запросы отклоняются. Автоматических повторов нет.
- Форма блокирует параллельную отправку и соблюдает паузу от HTTP 429 либо Google.
  Клиентская блокировка нужна для UX; серверные квоты работают без неё.

## Развёртывание

Обычная сборка: `npm run build`. Для Docker `.env*` исключены из контекста:
передайте публичную настройку через аргумент сборки. Секреты в `VITE_*` запрещены.

```powershell
$leadEndpoint = (Get-Content frontend/.env.production | Where-Object { $_ -match '^VITE_LEAD_ENDPOINT=' }) -replace '^VITE_LEAD_ENDPOINT=', ''
docker build -t secureguard-landing --build-arg "VITE_LEAD_ENDPOINT=$leadEndpoint" frontend
docker run --rm -p 127.0.0.1:8080:80 --log-opt max-size=10m --log-opt max-file=3 secureguard-landing
```

Для панели подключите контейнер к сети с реальным `backend:8000`.
Без backend публичный лендинг запускается, API возвращает ошибку доступности.
Используются Node 24 и актуальный stable Alpine nginx. При релизах пересобирайте
с `--pull` и проверяйте уязвимости образов: смена тега не обновляет запущенный контейнер.

После изменения `Code.gs` нужно сохранить код и обновить существующее развёртывание
Apps Script на новую версию. GET `/exec` возвращает `{"service":"secureguard-leads","version":2}`.
Настройки выполнения и доступа при этом обновлении не расширялись.

## Граница защиты от DDoS

Эти ограничения снижают нагрузку от HTTP-флуда и спама. Они не защищают канал сети
от объёмной распределённой атаки. Для внешнего сайта нужна защита на стороне
хостинга/CDN/WAF и закрытый прямой доступ к origin. Она здесь не подключена.

Публичный `/exec` Google вызывается напрямую и обходит nginx. Даже отклоняемые
вызовы могут расходовать лимиты выполнения Google. Для более сильной защиты
нужен приёмник под контролируемым шлюзом с серверной проверкой CAPTCHA/Turnstile
и закрытым внутренним способом записи в Sheets; CORS или скрытый URL этого не заменяют.

За CDN корректный IP нужно получать только от явно доверенных прокси, иначе
лимиты будут общими для посетителей. Не включайте доверие ко всем входящим XFF.
Исходный backend расположен в другом проекте; его авторизация, БД и квоты отдельно
не аудировались. Общий доступ к таблице оставлен по ранее подтверждённому выбору пользователя.
