# SecureGuard — публичный лендинг и существующая панель

Лендинг доступен на **`/landing`** и `/landing/` без авторизации. `/` и прежние
маршруты (`/cameras`, `/zones`, `/incidents`, `/pos`, `/analytics`, `/staff`,
`/settings`, `/phone-camera`) сохраняют поведение исходного приложения.

## Запуск

Нужен Node.js, совместимый с Vite 8. Проверено на Node 22.17.1.

```powershell
npm --prefix frontend ci
npm run dev
```

Открыть **http://127.0.0.1:5175/landing**. Рабочая панель: http://127.0.0.1:5175/.
Dev proxy направляет `/api` на `http://localhost:8001`, как в исходном проекте.
Для реального входа в панель нужен исходный backend; он не копируется и не запускается этим проектом.

```powershell
npm run build
npm run lint
npm test
npm run preview
```

Готовые статические файлы: `frontend/dist`.

## Что реализовано

- Русские тексты, адаптивный первый экран, возможности, сценарии, процесс, пилот,
  FAQ и форма. Неподтверждённых тарифов, результатов, клиентов и отзывов нет.
- Интерактивный макет карточки: три сценария, связанные POS-примеры, выбор времени
  и три решения оператора. Все данные демонстрационные; фотография — иллюстрация,
  а временная шкала — макет, не реальная видеозапись.
- Навигация, мобильное меню, FAQ, видимый фокус, reduced motion, валидация формы,
  ожидание ответа, ошибки и подтверждение с номером принятой заявки.
- Оптимизированная фотография кассы (186 KB вместо исходных 2.16 MB), логотип,
  favicon, title и description. Autoplay-видео и внешних шрифтов нет.
- Публичная страница загружается отдельно: Chakra, панель, MSW и камера не нужны
  для её открытия. Исходные компоненты панели сохранены.

## Приём заявок

Подключена Google Таблица SecureGuard, лист **«Заявки»**:
[настройка, схема и результат проверки](docs/GOOGLE_SHEETS_SETUP.md).
Серверный обработчик `integrations/google-sheets/Code.gs` опубликован в Google Apps Script.
19 октября 2026 выполнена отправка из браузера: форма получила номер заявки,
а соответствующая тестовая строка прочитана обратно из Google Sheets.

Публичный адрес обработчика задан в `frontend/.env.production`, поэтому обычная
production-сборка уже включает приём заявок. Для текущей локальной разработки адрес
также задан в игнорируемом Git файле `frontend/.env.local`.
После клонирования для dev можно скопировать `VITE_LEAD_ENDPOINT` из `.env.production`
в `.env.local`; production-сборке дополнительная настройка не нужна.

Для подключения другого API задайте в `frontend/.env.local`:

```dotenv
VITE_LEAD_ENDPOINT=/api/leads
```

Значение — доверенный same-origin путь либо HTTPS URL вашего приёмника. Это
публичная настройка frontend, **не место для секретов**. После настройки пересоберите сайт.
Endpoint должен сохранять заявку до ответа, валидировать поля и согласие на сервере,
ограничивать частоту запросов и при необходимости поддерживать CORS для домена сайта.
Не включайте auth-token панели в публичную форму.

Запрос `POST`, для обычного API `Content-Type: application/json`, для Apps Script
`text/plain;charset=utf-8` с тем же JSON-телом:

```json
{
  "name": "Имя",
  "contact": "owner@example.test",
  "city": "Алматы",
  "registers": 1,
  "equipment": "Описание камеры и POS",
  "source": "secureguard-landing",
  "consent": true,
  "requestId": "f74e4f2a-f42d-45e2-8bac-a85540d31880",
  "website": ""
}
```

Успех — только HTTP 2xx и JSON с явным подтверждением:

```json
{ "accepted": true, "requestId": "id-сохранённой-заявки" }
```

Пустой ответ, HTML от SPA fallback, `accepted: false`, ответ без номера, сетевой
сбой и тайм-аут не считаются успешной отправкой. После тайм-аута нужно уточнить
статус до повтора; автоматических повторных отправок нет. При повторе неизменённой
анкеты в открытой странице используется тот же UUID, чтобы не добавить дубликат.
Если `VITE_LEAD_ENDPOINT` пуст, отправка выключена и доступно локальное скачивание TXT;
анкета не сохраняется в localStorage.

## Перед публикацией

1. При смене хостинга проверить `VITE_LEAD_ENDPOINT` в окружении сборки и выполнить
   контрольную отправку уже с опубликованного домена. Локальный сайт проверен.
2. Добавить подтверждённые контакты команды, сведения об операторе данных и
   согласованную политику обработки данных; сейчас они не выдуманы.
3. Подключить домен и HTTPS, заменить `og:image` на абсолютный URL изображения
   `https://<ваш-домен>/brand/secureguard-logo.png`, добавить абсолютные `og:url` и canonical для `/landing`.
4. Настроить SPA fallback на `index.html` для frontend-маршрутов; `/api` направлять
   к реальному backend, а не к HTML. Готовая конфигурация: `frontend/nginx.conf`.
5. Если публикуется и панель, отдельно настроить `VITE_API_URL`, доступ к backend
   и инфраструктуру исходного SecureGuard. Не включать mock/demo по умолчанию.

Документация реализации и фактических проверок: [docs/LANDING_IMPLEMENTATION.md](docs/LANDING_IMPLEMENTATION.md).

## Защита и очистка

В nginx настроены лимиты запросов и соединений, ограничения размеров и времени ожидания,
защитные заголовки и CSP лендинга. В Google-обработчике — постоянные квоты, ограничение
по контакту и объёму таблицы. Форма соблюдает паузу при перегрузке.
[Лимиты, проверка и развёртывание](docs/SECURITY.md).

Эти настройки nginx действуют при запуске production-контейнера; Vite dev/preview их
не применяет. Для Docker передайте публичный `VITE_LEAD_ENDPOINT` через build argument:
файлы `.env*` исключены из Docker-контекста. Обычный `npm run build` читает `.env.production`.

Устаревшие скриншоты, скачанные тестовые анкеты и журналы прежних браузерных проверок
удалены. Рабочие изображения, исходник логотипа, история Git и документация сохранены.

продукта, **не результаты текущей проверки лендинга**.
